# PACK3 — Content Pack + Route Pack Expansion

## Purpose

PACK3 upgrades AndyAI Website Forge from a basic site scaffold generator into a controlled content-and-route driven website generator.

The generator must now read structured inputs and transform them into visible pages:

```text
Site Blueprint
+ Content Pack
+ Route Pack
→ generated public website scaffold
→ route-aware pages
→ reusable content sections
→ verification
→ evidence
```

## Canon

A website is not only a folder of pages.
A website is a structured public artifact system.

Website Forge must treat content as production material, not random text.
Routes must be declared, verified and explainable.
Pages must be generated from governed input packs.

## PACK3 scope

PACK3 adds:

- expanded content pack example
- expanded route pack example
- content section contract
- route metadata contract
- generated homepage sections
- generated navigation
- generated route pages
- generated project cards
- generated signal cards
- generated CTA blocks
- generated visual slots
- PACK3 verification
- generator evidence

## What PACK3 does not do

PACK3 does not add Supabase.
PACK3 does not add auth.
PACK3 does not add database logic.
PACK3 does not add monetization.
PACK3 does not add client upload.
PACK3 does not add runtime AI calls.
PACK3 does not deploy to Vercel.

## Output standard

A generated site must include:

- `README.md`
- `package.json`
- `app/layout.tsx`
- `app/page.tsx`
- route pages from route pack
- `app/globals.css`
- `public/visuals/.gitkeep`
- `docs/SITE_GENERATION_EVIDENCE.md`
- `docs/CONTENT_ROUTE_PACK_EVIDENCE.md`

## Canon formula

```text
Blueprint gives identity.
Content Pack gives story.
Route Pack gives structure.
Generator produces artifact.
Verifier produces trust.
```
