# 🅰️ AndyAI Website Forge

**A controlled production system for creating new public websites from verified content, visual, routing, deployment and QA patterns.**

## Core Formula

```text
Idea → Blueprint → Content Pack → Image Pack → Site Scaffold → Build → QA → GitHub → Vercel → Domain → Public Website
```

Website Forge is the future AndyAI system for creating serious public websites quickly without losing structure, proof, visual quality, safety boundaries, or deployment discipline.

## Project Identity

- **Project:** AndyAI Website Forge
- **Repo:** `andyai-website-forge`
- **Future domain:** `forge.andyai.ai`
- **Type:** Website production system / site generator / TAP-TAP web factory
- **Initial scope:** docs, specs, scripts, evidence

## Boundary

`andyai-main-site` remains the central public pillar of the AndyAI ecosystem.

`andyai-website-forge` is a separate production system for creating new public websites using AndyAI methodology.

Do not mix the two.

## What This Repo Does First

PACK1 does not create a full generator yet. It creates the foundation:

- Website Forge canon
- architecture map
- site blueprint schema
- content pack schema
- image pack schema
- route pack schema
- QA pack schema
- example site blueprint
- safety boundaries
- verification scripts
- bootstrap plan for future new sites
- evidence file for PACK1

## What This Repo Does Not Do Yet

- No Supabase
- No auth
- No database
- No monetization
- No client data
- No runtime AI calls
- No changes to `andyai-main-site`

## Canon

A website is not only pages.

A website is a public artifact system:

```text
Story → Structure → Visuals → Proof → Deployment → Trust
```

Website Forge does not replace design judgment.
It packages design judgment into a repeatable production flow.

Website Forge does not replace the human.
It gives the human a controlled factory for turning ideas into public digital artifacts.
